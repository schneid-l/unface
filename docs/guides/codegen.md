# Guide: codegen with `unfacegen`

**What this page covers.** What `unfacegen` does, why you'd use it, and how to invoke it today. CLI flag reference lives in [reference/codegen-cli.md](../reference/codegen-cli.md).

## What it does

`unfacegen` inspects a Go package, finds the types you name, and emits an `Unface(src any) error` method for each one. The generated method is a type switch that dispatches to whichever specific `Un*er` methods you've hand-written on the type.

**Why?** The dispatcher prefers `Unfacer` over the specific interfaces (step 3 in the [dispatch order](../dispatch-order.md)). Types with a generated `Unface` skip the per-call reflection in step 5 and hit the compiler-checked fast path instead. For a performance-sensitive binding loop, this is a meaningful saving.

## Install

```bash
go install github.com/schneid-l/unface/cmd/unfacegen@latest
```

## Basic usage

Given:

```go
// file: traffic.go
package traffic

type Light int

func (l *Light) Unstring(s string) error { /* ... */ }
func (l *Light) Unnumber(n unface.Number) error { /* ... */ }
```

Run:

```bash
unfacegen -type=Light
```

This writes `light_unface.go` next to the source:

```go
// Code generated by unfacegen; DO NOT EDIT.
package traffic

import "github.com/schneid-l/unface"

func (recv *Light) Unface(src any) error {
    switch v := src.(type) {
    case string:
        return recv.Unstring(v)
    }
    if n, ok := unface.NumberOf(src); ok {
        return recv.Unnumber(n)
    }
    return unface.ErrNotHandled
}
```

## Multiple types

Comma-separate them; the output file is derived from the first:

```bash
unfacegen -type=Light,Car,Road
# writes light_unface.go covering all three
```

Or name the output:

```bash
unfacegen -type=Light,Car,Road -output=generated.go
```

## `go generate` wiring

Add a directive near the types:

```go
//go:generate unfacegen -type=Light,Car,Road
```

Then `go generate ./...` regenerates whenever the types change.

## What gets generated

For each requested type, `unfacegen` reads the method set of `*T` and emits:

- A `case T:` branch for each matching `Un*er` method (string → `Unstring`, bool → `Unbool`, `[]byte` → `Unbytes`, `rune` → `Unrune`, `time.Time` → `Untime`, `time.Duration` → `Unduration`, `nil` → `Unnil`).
- An `if n, ok := unface.NumberOf(src); ok` block when `Unnumber` exists.
- An `if l, ok := unface.ListOf(src); ok` block when `Unlist` exists.
- An `if m, ok := unface.MapOf(src); ok` block when `Unmap` exists.
- A final `return unface.ErrNotHandled` so unmatched kinds fall through to plugins.

If the type already declares `Unface`, the generator leaves a skip comment rather than overwriting — hand-written `Unface` always wins.

## Walker mode: tag-driven generation

When you have a plain struct — no hand-written `Un*er` methods, just fields and `unface:"..."` tags — use `-mode=walker`. The generator reads the struct layout and emits an inlined equivalent of the runtime `StructPlugin` with zero reflection at runtime.

```go
// file: config.go
package traffic

type Config struct {
    Host    string `unface:"host,required"`
    Port    int    `unface:"port"`
    Tags    []string
    Secret  string `unface:"-"`
    Backend string `unface:"backend,alias=server,alias=upstream"`
}
```

Run:

```bash
unfacegen -mode=walker -type=Config
```

The emitted `Unface` method calls `plugin.MapOf(src)`, looks up each field's primary key (and aliases, if any), recurses into `unface.Unface` for the field value, and — for `required` fields — emits a post-pass missing-key check that wraps `plugin.ErrRequired`.

Supported tag modifiers in v1 of walker mode: **positional name, `-` (skip), `required`, `alias=`**. Anything else (`remainder`, `inline`, `strict`, `match=`) is rejected — use the runtime `StructPlugin` if you need those. See [reference/codegen-cli.md](../reference/codegen-cli.md#walker-mode) for the full matrix.

## Limitations (today)

- Walker mode only honors a subset of the tag grammar (name, `-`, `required`, `alias=`). The rest of the grammar lives in the runtime `StructPlugin`.
- Walker mode always generates exact-match key lookups; `-matchmode=fold|insensitive` is accepted for CLI symmetry but doesn't change the emitted code. Use the runtime walker for case-insensitive matching.
